# Catalog sources

`data/catalog.json` = 79 hand-curated seed entries (never modified) + entries generated by `scripts/build_catalog.py`.

## Sources (download yourself; raw files are not committed)
1. Wikipedia, "List of GameCube games" (title, developer, earliest release year, alternative titles used as aliases):
   `https://en.wikipedia.org/w/api.php?action=parse&page=List_of_GameCube_games&prop=wikitext&format=json&formatversion=2`
   (send a descriptive User-Agent; the API rate-limits anonymous clients). The page is one big table; it has no genre column,
   so `genres` and `tags` of generated entries are empty. Rows released in no region ("Unreleased" everywhere) are skipped.
2. GameTDB title list: `https://www.gametdb.com/wiitdb.txt?LANG=EN` (`ID = Title`; mixes Wii and GameCube; no
   GameCube-only export was found: `gcdb.txt` redirects). Only IDs `G??E??` are used, `code4` = first 4 chars.

## Rebuild
    python scripts/build_catalog.py --wiki wiki.json --gametdb wiitdb.txt --catalog data/catalog.json --out data/catalog.json
Idempotent; existing entries are kept as they are, new ones appended.

## code4 policy
Attached only when a GameTDB title (without brackets/parentheses) equals the Wikipedia title under exact normalized equality
(`pawtation.core.norm` plus accent stripping and `$` -> `s`) and that code4 is used by exactly one title in the whole list
(hacks and mods of popular games reuse codes, e.g. GM4E, GLME, GMSE; those are never auto-assigned). A title mapping to two
different code4 values is omitted, as is any code4 already used by another entry. Hand-reviewed alias table
(`TITLE_ALIASES` in build_catalog.py): currently empty.

## Known issue
Seed entry `soulcalibur-ii` has `code4` `GS2E`, but GameTDB lists GS2E as "Summoner: A Goddess Reborn" and Soulcalibur II as
`GRSE`. Seed entries are left untouched by the generator; fix by hand.

## import_ids.py
`python scripts/import_ids.py ids.txt [--apply] [--catalog PATH]` merges a user-supplied `ID = Title` file (dry-run by default).
